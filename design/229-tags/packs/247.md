## Rulings that override or extend the boards
- **A plain click on a rendered `#tag` opens Tags mode** (Spec R21, L18/D19a), and so does Cmd+click. Flow F3 shows typing only and no board draws a plain click; the underline is Cmd-hover only. Both clicks call `revealTag(tag)` (#251), never `follow`: #232's `follow` handles note navigation, a tag click records none.
- A person-written `#inbox` (or `#agent-authored`) opens Tags mode with the `System` group expanded (R20); `revealTag('inbox')` does that.

## Cmd-hover look (B4 "Cmd held over a tag")
| state | tag colour | decoration | cursor |
|---|---|---|---|
| rest | `fg2` #9B9A94 | none | text |
| Cmd held and pointer over the tag | `accentSoft` #4FCF8A | solid underline, text colour | click (`SystemMouseCursors.click`) |
| Cmd released | back to `fg2`, underline gone | | |
- The ink is #245's; this WI feeds the existing `cmdHover` range for tag tokens (the `hover` flag in `livePreviewTextStyle` already underlines) and flips #232 N6's followable predicate for tags.
- The underline is on the tag token only (`#work`), not the line. Caption: "accentSoft plus underline and click cursor, so a grey tag still shows it's a link."
- Excerpt cards (B4 "Tag inside a transcluded excerpt"): identical: `fg2` at rest, `accentSoft` + underline with Cmd, click opens Tags mode. The card is `surface3` with a 1 px `line2` border, radius 6. The tag does not count as a tag of the note that shows the card.
- Design is silent on the cursor and any hover change over a tag **without** Cmd (plain click is a late ruling). Don't invent one: keep the text cursor and no underline; flag to Connor if discoverability is wanted.
- Design is silent on the selection ink; the caret-inside ink is `accentSoft` with no underline (B4 "Cursor on a tag").
- A click elsewhere in the line places the caret as today; only a press that starts on the tag's glyphs is the tag's.

## Flow F1 (browse by tag; what each board shows)
1. **F1.1** Tags mode, every tag collapsed, daily note `2026-11-06` open (tab bar: one tab).
2. **F1.2** `#work` row clicked: name `accentSoft`, chevron down, its 7 notes listed under it (`2026-11-06` active on `surface4`).
3. **F1.3** a note row (`Pricing`) clicked: `follow(NoteTab)` opens the `Pricing` tab (second tab, active `surface3`); `#work` stays expanded, the `Pricing` row is now the active one.
4. **F1.4** the tag `#pricing` chosen in the open note (footer or rail; the same call as an inline click): sidebar jumps to `#pricing` expanded (name `accentSoft`; notes `2026-11-06`, `Pricing` active, `2026-11-02` with its first line), **`#work` is collapsed again**; the open note is `Pricing`. The meta rail and footer of the open note are unchanged.

## Open question for the lead
F1.4 shows only `#pricing` expanded after `#work` was expanded in F1.3. Neither the WI nor Spec R26-R32 says whether `revealTag` collapses other tags or whether expansion is single-select. The board reads as single-select (accordion). #251's pack repeats this; settle it once in #251's `tags_browse_state.dart`.
