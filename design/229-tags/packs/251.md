## Behaviour and flow F1
- B1 = F1.2 state: Tags mode with `#work` expanded, `2026-11-06` active (open tab). F1.1 all collapsed. F1.3 a row click opens the note (`follow(NoteTab)`, once) and the clicked row becomes active. F1.4 `revealTag('pricing')` from a note: sidebar shows `#pricing` expanded and **`#work` collapsed**.
- `revealTag(tag)` switches the mode, expands the tag (or `System` for `inbox`/`agent-authored`) and scrolls it into view.
- The active row follows `activeTabProvider`, not `tabs.indexOf`.

## Real components vs the board
- Not reusable: `topics_pane.dart` `_FolderRow`/`_NoteRow` are Inter Tight 13, 13 px icons, folder glyphs, padding 4, radius 5 and a menu button. Tags rows are their own mono 12, 24 px rows (private widgets in `sidebar/tags_pane.dart`). Reuse only `VaultAsyncView`, `Eyebrow`, `OmColors`/`OmType` and the switch.
- No `OmChip`, no folder or hash icons, no header, no drag targets.
- Footer-only tag notes have no first line, so those rows are title-only (22 high).

## WI vs design (design wins) and gaps
1. **B2 cell 8 uses a tag name with `/`** (`#work/pricing-and-renewal…`). Spec R7 makes tags flat: `#work/pricing` is the tag `work`. A real name can't contain `/`; use a long hyphenated name in tests (`pricing-and-renewals-2027-planning-draft`).
2. **Single vs multi expansion**: F1.4 collapses `#work` when `#pricing` is revealed; the WI and Spec don't say. Treat as single-select unless told otherwise. A tap on an expanded row collapses it (WI).
3. System-child note rows and all hover/focus states are not drawn (above).
4. WI says "copy for the empty states comes from the Sketch file": cells 4, 5 and 7 are the single line above; there is no separate error text for Tags mode.
