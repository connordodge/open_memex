## PaletteRow, command / note / daily / canvas (board C1, C2, N1)

Row: height 32, width = list column inner (387 in the 400 column, 626 at 640), horizontal padding 10, vertical 0, gap 10, radius 6, children vertically centred.
Unselected: no fill. Selected (and hovered; the board draws one look): fill `surface4`.
Children left to right:
1. Kind icon, 14x14 box, glyph size 14, `fg2`.
2. Title, `OmType.sans` 13.5, line height 16.06 (height 1.19), weight 400, `fg0`, takes the remaining width, one line, ellipsis. Matched characters (from `fuzzyMatchPositions`) are separate runs in `accent`, same size and weight (C2: `Back|ups`, `Back|log`, `Feed|back| log`; `Show right |panel|` in C5).
3. Meta (optional), `OmType.mono` 10.5, line height 13, weight 400, letter spacing 0, `fg2`, right aligned, never wraps.
4. `↵` chip, selected row only, list-only layout only (see mismatch 1): 23x18, horizontal padding 5, border 1 `line3` inside, radius 4, glyph `↵` `OmType.sans` 10.5, letter spacing 0.2, `fg2`. Gap 10 after the meta; with no meta the chip is flush right (C4 state 10, N1).

| Kind | Icon (Lucide) | Meta text drawn |
|---|---|---|
| command | per command, see table below | none, except Open today `2026-11-18` (ISO date) and the current sidebar mode's Show row `shown` |
| note | `file-text` | `note · 2 h ago`, `note · 4 d ago`, `note · 3 w ago` |
| daily | `calendar` (title is the date, `2026-11-18`) | `daily · today`, `daily · 1 d ago` |
| canvas | `layout-dashboard` | `canvas · 1 d ago`, `canvas · 2 w ago` |
| passage | `text-quote` | `note · 2 h ago`, `daily · 6 d ago`; the `via <YYYY-MM-DD>` meta is not drawn (see notes) |

Meta format: `<kind> · <n> <unit> ago`, unit `h`, `d` or `w`, one space between number and unit, ` · ` is space, U+00B7, space. `today` replaces the age for a daily note of today. Units below an hour, months and years are not drawn.
Recent rows (empty input, C1) use the same row, with no matched characters.

## WI mismatches (the design wins)

1. The WI says a selected `PaletteRow` shows a `↵` chip. The design draws the chip only in the **list-only layout** (N1, and every C4 card): the wide card (C1, C2, C5, F4, F5) draws a selected row with `surface4` fill and **no chip**, because its preview footer already names `↵`. So `PaletteRow` needs a `showEnterChip` flag, true when the preview pane is absent. A test "selected row shows a chip" should pump the narrow card.
2. The WI says passage text is clamped to 2 lines. N1 (640 wide) draws up to 2 lines (row 69). The 400 px list column (C2, C4, F4, F5) draws **one** line ending in `…` for the same kind of text (row 51), which looks hand-truncated on the board. Build the 2-line clamp (`maxLines: 2`, ellipsis); the lead should confirm with Connor whether the 400 px column is meant to be one line.
3. The WI's "mark highlight (accent at 15 %)" matches the board (`accentMark` = `#7CFFB226`), but no `accentMark` token exists in `colors.dart`; add it (see Tokens).
4. The `via <YYYY-MM-DD>` meta of a `via` hit is not drawn on any board; it takes the same meta slot as `note · 2 h ago` (mono 10.5, weight 500, `fg2`, right aligned). The row's other text (title, passage text) is as drawn.
5. Hover and keyboard-selected look the same here: `surface4`. A pressed look and a focus ring are not drawn.
6. Some layer names in the Sketch file use an older word for passage text (a naming leftover). UI copy and code names say "passage".
