## Keyboard focus (`.ib:focus-visible`, `.ib.focus`)
- Ring: `outline: 2px solid #7CFFB2; outline-offset: -2px` = 2 px `OmColors.accent` ring drawn INSIDE the 24 x 24 box, outer edge
  flush with the box edge, following the 6 px radius. The size does not change (draw as `foregroundDecoration` with
  `Border.all(accent, width: 2)` and radius 6, not as extra padding).
- Background while focused: `#20262E` = `OmColors.surface4`, fixed. It does not depend on `hoverBackground` or the kind.
- The ring shows for keyboard focus (CSS `:focus-visible`): the focus-highlight-mode "traditional" equivalent. A click must not
  leave a ring.
- Tab order, Enter/Space and semantics are behavioural (WI ACs); the board only draws the look. Disabled focusable buttons keep
  focus (lead ruling in the WI) and keep the focused look while focused.

## Tooltip (`.tip`, drawn on hover and on focus). No AC in this WI; do NOT restyle.
`position: absolute; top: 30px (below the 24 px button + 6); right: 0` (hover tip uses `right: 26px`), `white-space: nowrap`,
bg `#2A313A` = `OmColors.surface5`, text `#F4F1EA` = `OmColors.fg0` Inter Tight 11.5 / line-height 1.3, padding 5/8, radius 5,
shadow `0 4px 12px rgba(0,0,0,.5)`. Measured: "Move to…" tip 65.11 x 24.94; "Remove from Player Loop" 142.48 x 24.94.
The app has no `TooltipThemeData`; `OmButton(tooltip:)` wraps the Flutter default `Tooltip`. Tests pin the message only.

## Copy used by the buttons this opt-in serves (labels, verbatim)
`Move to…` (`arrowRightLeft`), `Remove from <Topic title>` (`x`), `File in…` (`folderInput`); icon-only, so `tooltip:` is also
the semantics label (WI AC).

## States this WI must show / test

2. Hover with `hoverBackground: surface4` (`.ib.hover`).

4. Disabled: 40% opacity, still focusable when `focusable: true`.
5. Without the opt-ins: hover = kind default (ghost surface3), icon 12 dense / 14, not a focus stop.
