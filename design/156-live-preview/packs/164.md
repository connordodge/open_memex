## WI vs design (design wins)
1. **H3** line height is 28.5 (WI #161's 32.3 is wrong); weight: CSS 600, the Sketch (the only installed bold is 700) draws 700, so use `FontWeight.w700` for H1–H3.
2. **Strike colour:** a `~~struck~~` span is line-through **and `fg2`** (A1 "flutter_markdown"), the same as a done task; the WI only names the done-task case.
3. **Quote rows** (`> `) render their text **italic in `fg1`** (A1/A4-M); the C1 row props (`itemText`, `taskDone`) have no quote flag. B1 needs an optional `quote: true` prop (C1 sets it) or the italic/`fg1` has no home. Report to lead.
4. Wikilink `~kind|alias` revealed: everything but the alias is one `fg2` run (see below).

## Revealed markers (segment focused, caret/selection touches the logical line)
- Whole logical line reveals (a wrapped paragraph reveals all its wrapped lines: A4-B, F1.3).
- Marker style: **`fg2`, w400, upright, no decoration, at the line's own font size** (the `## ` of an H2 is 17 px regular `fg2`; `**` is not bold even inside a bold span). Width = chars x column advance (8.1 at 13.5).
- Selected marker (inside a selection) and selected done-task text: **`fg1`** (see pack #159 for ratios).
- Markers per token (A4-B): `**`/`*`/`~~` `fg2` around the styled text; `` ` `` `fg2` around code (pill stays under the content only); `[` and `](url)` `fg2` (the `(https://…)` run is not underlined) with the text still `info`+underline; `[[` and `]]` `fg2` with alias `accent`; with kind and alias the run `[[Conflict merge~topic|` is one `fg2` run and `]]` `fg2`; ghost: brackets `fg2`, title `fg2` + dashed `fg3` underline under the title only.
- Hidden: zero-width; the line keeps its height.
- Heading line revealed (A4-A): `## ` `fg2` regular + `Today` bold `fg0`; height unchanged (34).
- Task/bullet/quote/number markers live in C1b's marker column, not in the span (see pack #168).

## Fenced code (A4-D, A1)
- Caret outside the block: both fence lines hidden (height 8.0 each, pack #161), code lines `fg1`.
- Caret on any line inside: both fence lines show `fg2` including the info string (`` ```dart ``), whole line `fg2`; code lines stay `fg1`, unstyled.
- A horizontal rule's `---` characters are hidden off the caret line (B2 paints the line); on the caret line they show as `fg2` markers (design silent; the board's rule is never under the caret).

## Cmd-hover and hover hooks (set by B3; values from boards A4-F, F2.1–F2.3)
| state | resolved link `[t](u)` | resolved wikilink | ghost |
|---|---|---|---|
| plain hover / click | no style change, text cursor | no change, text cursor | no change, text cursor |
| Cmd held + hover | no visible change (already underlined); pointer | **underline added**, 1 px, in the token's own colour (`accent`); pointer | **nothing**: no underline change, text cursor |
So the `cmdHover` style is `TextDecoration.underline` on the hovered wikilink token; for a link it is a no-op.
