## WI vs design (design wins)
1. **H3 line height is 28.5, not 32.3.** CSS `.h3` = 15 x 1.9 = 28.5; every H3 line in A1, A2, A3 and A4 is 28.5 high. (32.3 = 17 x 1.9, the H2 size.) H1 = 20 x 2 = 40 and H2 = 17 x 2 = 34 match the WI.
2. **Hidden fence line height = 8.0** (derived, see below); the WI says "from the design pack".

## Mono column
JetBrains Mono advance = 0.6 em: **8.1 px at 13.5** (A1 col widths 16.19 / 24.3 / 32.39 / 48.59 = 2/3/4/6 x 8.1, within rounding). At heading sizes: 12.0 (H1 20), 10.2 (H2 17), 9.0 (H3 15).

## Marker column widths (columns, pixels = columns x 8.1)
| kind | unrevealed | revealed (caret/selection on the line) |
|---|---|---|
| bullet (`- `, `* `, `+ `) | 2 = 16.2 | 2 |
| numbered | digits of the run's widest number + 2: 1-digit run 3 = 24.3, 2-digit 4 = 32.4, 3-digit 5 = 40.5 | same |
| quote (`> `) | 2 = 16.2 | 2 |
| task (`- [ ] `, `- [x] `) | 4 = 32.4 | **6 = 48.6** (text shifts 2 columns; only that item) |
Numbered run: every row in a run has the run's width (A2 board: `1.`..`10.` all 4 cols). Painted number is right-aligned with a 1-column right padding: left edge = colLeft + width − 8.1 − textWidth (so `9.` at +8.1 and `10.` at +0 in a 4-col column; the `.` characters line up). Revealed numbered marker source is drawn from the column's left edge.

## X positions (text column left = T)
- **Text column left T:** daily note = field left + **14** (the capture gutter, `captureGutterWidth = 14`, holds only the 2 px rule at gutter x + 6; A1 field x 180 → T = 194; A2 field x 28 → T = 42). Topic note field has no gutter: T = field left (A3: 180).
- Column width is min(760, window − 56): A1 760, A2 664; text column = that − 14 on a daily note (746 / 650).
- Item marker column x = T (level 1). **Item text x = marker x + column width** (bullet 16.2, task 32.4, 1-digit numbered 24.3 …).
- **Nesting (R12):** a child's marker column x = its parent's *unrevealed* text x; child text x = child marker x + child width. A2: bullet child of a bullet at T + 16.2 (text at T + 32.4); bullet child of the `10.` row (4-col run) at T + 32.4 (text at T + 48.6); revealing a parent task (32.4 → 48.6) never moves its children. In the file, two spaces of indent = one step; the leading spaces are never drawn.
- Wrapped item lines start at the item text x (hanging indent). Right edge of item text = T + text column width (no right inset), except quote rows: **1 column (8.1) right padding**.
- Prose and blank lines start at T.

## Code fence geometry (for the hidden fence line height)
A1 code box = 61.88 tall: 2 code lines x 22.94 + **8 + 8**, where 8 = 7 px padding + 1 px border. The blank line above/below is a normal 22.95 line. So a hidden fence line is 8.0 tall when the box rect = first fence line top → last fence line bottom (hidden-state box matches the board exactly).
Revealed (A4-D) = 107.75 = 4 x 22.94 + 8 + 8: the board keeps the 8 px padding when both fence lines show (fence lines would be 30.94 each with the text at the bottom/top). Recommended mapping: revealed fence lines 22.95 and the box painter outsets the rect 8 px up and down in the revealed state only (it lands in the neighbouring blank lines, never in the gutter). Content below then sits 16 px higher than the board in that one state; lead to confirm.
**Open (needs lead/Connor):** the board insets code text **16.2 px (2 columns) from the box's left edge and 10 px from its right**; a TextSpan cannot indent only fenced lines, and the box may not paint left of T (R6). Fallback: text flush at T with the box from T.
