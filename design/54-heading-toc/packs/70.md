## Where the design differs from or adds to the WI (the design wins)
1. **The design draws focus only on a non-current row.** State e / P3: ring on row 5 `South bed`, current stays row 10 `Summer`. Focus on the current row (what ⌘⇧O does first) is not drawn: derived below.
2. **The keycap is a hint, not a button.** Board 1's `Keycap ⌘⇧O` is only the prototype trigger into P3; nothing in the design says it is clickable. Keep it a non-interactive hint (the WI says "keycap sits in the header").
3. No design for Esc, Space/Enter feedback or a focus ring while the Outline has no focus. Derived rules below. The jump itself (flash, 16 px) is pack #69.
4. The caption of state e reads "⌘⇧O, then ↑ ↑ ↑ ↑ ↑": from the current row (10) five ups reach row 5, which the WI's roving index must reproduce (up stops at row 0).

## Focus ring (state e, P3)
- Row 5 `h3 · South bed`, row 339 x 26 (window coords x 1101, y 225 in P3), depth 2.
- **2 px `accent` `#7CFFB2` ring, inside the row bounds, square corners, no fill.** It spans the whole row width including the 16 px side padding, so it touches the panel's inner edges (the panel's 1 px `line1` border is outside it).
- Content stays put: tag at x 16, guides at x 42 and 56 (1 px `line2`; the Sketch trims them to 22 px high inside the ring), text at x 66, all unchanged. In Flutter, draw the ring as a foreground border/painter with **no layout change**.
- Colours inside the ring: tag `fg2`, text `fg1` w400 (a non-current row), no hover fill unless the pointer is on it.
- Summer (row 10) in the same board keeps its current look: tag `accentSoft`, text `accent` w500, 2 px accent bar in guide column 1 (x 56 of the row), no fill. The two are drawn independently: **the ring never changes the current marks and the current marks never draw a ring.**

## Derived (not drawn): focus on the current row
`⌘⇧O` focuses the current row first, so this state is the most common. Draw the current marks (accent text, accentSoft tag, 2 px accent bar) **plus** the 2 px accent ring, still no fill. They are distinguishable: the ring is the outer 2 px frame of the row, the bar is a vertical 2 px stroke in a guide column at least 42 px from the left edge, and the text is inside both. Adding hover adds only the `surface3` fill under all of it (pack #68, "Combined"). Contrast of the ring: accent on `surface1` 15.49, on `surface3` 13.56 (non-text, needs 3).

## Keyboard behaviours that have a visual
| action | visual result |
|---|---|
| `⌘⇧O`, panel closed or another tab | panel opens on the `outline` tab (chip `outline` selected: fill `surface3`, `fg0`); ring on the current row, else on row 0; with no entries no ring (placeholder b) |
| Up / Down | ring moves one row, stops at row 0 and the last row (no wrap); the current marks do not move |
| Enter / Space | the jump (pack #69: flash, 16 px); the ring **stays** on the same row; that row becomes current right after the jump, so it shows ring + current |
| Esc | ring disappears (focus is back in the editor field); rows keep their current marks |
| list scrolls | the focused/current row is kept in view by scrolling the least needed (no design numbers; no animation drawn) |
Only one row has the ring at a time (roving index). Each row is a button; the current row is semantics `selected`.
