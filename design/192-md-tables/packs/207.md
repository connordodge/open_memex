## Click to caret (R21), primary plain click on a rendered grid
Grid-local point (origin grid top-left). Result = reveal the table, focus its row, caret at the field offset below.
| press | caret goes to |
|---|---|
| inside a cell's text (x within `[cellX + c, cellX + w - c)`, y within that cell's own text block, not the rule pixel) | the glyph boundary nearest the press, in the raw line, hidden markup counted (B3-B: click x 90 px into `Marker parser` = char 11, caret `**Marker pars\|er**`) |
| right of a line's last glyph, still inside the text block | that line's end (wrapped line: its last character) |
| a cell's left/right padding (8.1 strips), the rule pixel (row bottom - 1, non-last rows), the header band's top and bottom 4 px strips, below the cell's text in a taller row, an empty cell | **that cell's text end** (end of T1's trimmed raw cell range; hidden closing markers included) |
| left of the grid (x < 0) / right (x >= W) | column 0 / last column, then the rules above; above/below the grid clamp to the header / last row |
| a row's missing cell (row has fewer cells than the header) | the text end of that row's last present cell |
| header band | the header line's cells, same rules |
Worked, B1 grid (194,377.5; widths 290.11 / 300.47 / 82.89 / 72.53; band 0-30.95, body rows 30.95-53.9, 53.9-76.85, 76.85-99.8, 99.8-122.75), source line `| **Marker parser** in pure Dart | see [[Byte offsets]] | 1.5 | done |` (70 chars):
- (98.1, 42) = text x 90 in col 0 -> offset **15** (after `Marker pars`); T1.2 draws exactly this caret.
- (3, 42) left padding, col 0 -> offset **32** (after `Dart`, before ` \|`).
- (150, 53.4) on the rule under row 1, col 0 -> offset 32 again.
- (400, 2) header band top strip, col 1 -> header line, after `Notes` (offset **14** in `\| Step \| Notes ...`).
- (700, 110) row 4 (`\| Table reveal \| *ask Connor* \|`, 31 chars), col 3 missing cell -> offset **29** (after `*ask Connor*`).
- (740, 42) right padding of col 3 (673.47-746) -> offset **68** (after `done`).
- (300, 42) col 1, 1.8 px into the text (content left 298.21) -> offset **35** (before `see`).

## Multi-click, drag, secondary (design silent; Spec R21 and L7 govern)
- Double-click selects the word in the RAW text at the offset mapped at press time (B3-B step 2 shows the layout the reveal produces); triple-click selects that grid row's whole source line (the header or that body row's line; never the delimiter). The first click reveals and changes layout (below), so the second/third click must not re-target.
- Layout shift on reveal (what the multi-click must ignore): header text y 4 -> 0; body row r text top `30.95 + 22.95 r` -> `45.9 + 22.95 r` (+14.95); cell x positions replaced by raw-line x (`\| ` = 16.2 in); everything below +14.95 (pack #204).
- Drag / Shift+click from or into a rendered table: anchored at the offset mapped at press time, no extend before `kPrecisePointerHitSlop`; the table is revealed and the selection fill is `OmColors.selection` (pack #159 / #206). Secondary click: same caret/reveal as a plain click, the revealed field's context menu shows.
- Cursor: **text cursor over the whole grid** (T2.1: `Icon / cursor-text` 10 x 18, stroke 1.5 `fg0` outlined `surface0`). No pointer on cells, no hover style, no focus ring.

## Cmd and links (R22), values from T2.1-T2.3 and B3-F
| state | resolved wikilink in a cell | resolved `[t](url)` | ghost wikilink |
|---|---|---|---|
| plain hover / click (T2.1) | no style change, text cursor; click is the R21 click (reveal), no navigation | same | same |
| Cmd held + hover (T2.2) | **underline added**: 1 px, `accent` `#7CFFB2` (text `accent`, decoration underline, Sketch offset 3), pointer cursor (`Icon / cursor-pointer` 22 x 22, white hand with `surface0` outline, hotspot at the finger tip near the text) | pointer cursor, no visible change (already `info` + underline) | **nothing**: dashed `fg3` underline and `fg2` text unchanged, **text cursor** (T2.3 `Icon / cursor-text` at 456.31,179.41) |
| Cmd + click | save a pending edit, then `tabsProvider.openOrFocus(NoteTab(id))` once | URL opener once (http, https, mailto) | nothing opens. The board says a ghost ignores Cmd, so the press is handled as a plain click (reveal); WI AC 'does nothing' read as no navigation (see return notes) |
The cmdHover style is only `TextDecoration.underline` on the hovered wikilink token (pack #164). The link's hit rect is the glyph rect(s) of its range in that cell (`boxesFor`, a wrapped link has one rect per line), never the whole cell. B1 example `Byte offsets` (row 1, col 1): grid-local x 330.61 .. 427.81 (content left 298.21 + `see ` 32.4, 12 x 8.1 = 97.2 wide), y 30.95 .. 53.9. Links are found per cell through T1's splitter; the `isResolved`/`cmdHover` ranges are field offsets that T4 shifts to cell-local for styling (D16).

## Flows
T1: T1.1 (caret on the plain line above, grid shown) -> click `Hotspot · table row` (the first body row, 674 x 22.95) -> T1.2 (revealed, caret at offset 15) -> click `Hotspot · line below` -> T1.3 (grid again, caret at the end of the line below). T2: T2.1 plain hover (text cursor on `Byte offsets`) -> T2.2 Cmd held (pointer, accent underline) -> T2.3 Cmd over a ghost (text cursor, no change) -> back to T2.1.

## WI vs design
No numeric conflict. Clarifications: (1) the design has no `MouseRegion` on cells: the pointer/text cursors above are owned by the pointer layer (D14); (2) `[t](url)` with Cmd shows no visible change, so "the link's Cmd-hover style" is the underline on resolved wikilinks only; (3) the board B text says a click in an empty cell goes to the nearest cell text end: the missing-cell rule above is the implemented reading of it.
