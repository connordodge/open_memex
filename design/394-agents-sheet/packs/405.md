# Pack #405 U3: InlineError `Retry` text button

Source: canvas https://claude.ai/artifact/QS8G3MJjgPGEAHqVpxFQxM (approved 2026-11-11, no Sketch file, ruling R2).
**There is no error panel on the board.** `Main` and `States` hold no InlineError at all (States panels: 1 hosted Connect, 2 Claude Code
revealed, 3 Live no agents, 4/5 Recall off, 6 older server, 7 narrow, 8 entry points). Nothing here can be golden-tested against the board:
the numbers below are the existing widget's, plus a recommendation built from existing tokens. No PNG ships with this pack.

## Existing widget (keep byte-identical without `onRetry`)

`app/lib/src/widgets/inline_error.dart`: Key `inline-error`; margin bottom 8; padding L12 T4 R4 B4; radius 4;
fill `OmColors.dangerBg` (danger #FF7A8A at 10%); message `OmType.mono(size: 11, color: OmColors.danger)`; Row: message `Expanded`,
then dismiss `OmButton(key: inline-error-dismiss, kind: ghost, size: 22, icon: LucideIcons.x, tooltip: 'dismiss')`.

## Retry (recommended, not on board)

| Item | Value |
|---|---|
| Position | Row child between the message and dismiss, so the order is message, `Retry`, dismiss. Gap to dismiss 2 |
| Widget | `OmButton(key: Key('inline-error-retry'), kind: OmButtonKind.ghost, dense: true, size: 22, label: 'Retry', onPressed: onRetry)` |
| Label | `Retry` (sans 12 w500, from `dense`), colour fg1 #D6D3CC (`OmColors.fg1`) |
| Box | height 22, horizontal padding 10, radius 6, no border, no fill; hover fill surface3 #181D23 (`OmColors.surface3`) |
| Icon | none (a text button) |
| Semantics | label `Retry`, button role; keyboard-activatable (needs #393 U2 `OmButton(focusable:)`; the current OmButton is a `GestureDetector` with no focus) |

Why ghost: `OmButtonKind` is `primary, secondary, ghost, agent, danger`. **There is no `text` kind**, so the WI body's "OmButton (text kind)"
maps to `ghost` (transparent, no border, fg1 label). `danger` kind would draw a bordered chip next to the plain dismiss `x`, which is not a
text button. Do not add a new kind for this.

## Where it appears (copy comes from the tab WIs)

A failed read in Live, Tools, or Recall shows `InlineError(message: <CLI or server message>, onRetry: ...)` at the top of the tab body
(inside the 24 px body padding). `message` is the CLI one-line error or the hosted server's message verbatim; never a parse error (Spec req 29).
