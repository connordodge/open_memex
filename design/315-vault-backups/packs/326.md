## The row

Box (the tappable box): min height 28, width fills the 244 px; `border` 1 `line1`, radius 6, no fill; padding H10, V0 (V4 at larger text), row, gap 8, vertically centred;
pointer cursor `SystemMouseCursors.click`; `Focus` so Tab reaches it (a normal tab stop after the pills, never auto-focused), Enter and Space activate it.
Children: icon 12x12, label (sans 12.5, height 1.2, `fg1`), then the status text pushed right (mono 10.5, height 1.24, `fg2`).

The row only takes the warning look while the current destination's last result is an error (local) or the server's last result is an error (hosted), and no warning while backups are off.
It never opens a modal, never requests focus, never steals typing. A later success clears it. A press anywhere in the box (click, Enter, Space) opens `showBackupsSheet` once.

## Keys (frozen names; what each wraps)

- `backups-entry`: `KeyedSubtree` around the whole tappable box (the 244x28 bordered box, padding included; not the 12 px outer margin). The entry owns every press in its box.
- `backups-entry-warning`: wraps the badge only, drawn as the 12x12 amber `triangle-alert` icon (the board has no separate badge shape, see Notes). It sits inside `IgnorePointer`, so it takes no presses; it exists only while a warning shows.
  Text ("backup failed", the time) is asserted by text and semantics, not by this Key.
- No other Key is needed.

## Semantic label (state is text, never only colour)

Label = `backups for <vault>: <state>`, vault = the vault's folder name (hosted: its vault name). The hint "open backups" ends the label (B1 draws it after a dot). Drawn:

- off: "backups for memex: off. open backups"
- last backup: "backups for memex: last backup today at 14:03" (the board caption omits ". open backups"; treat it as the tap hint on every state)
- local failure: "backups for memex: the automatic backup failed today at 09:00, can't write to Google Drive. open backups"
- hosted failure: "backups for work: nas's backup failed today at 03:00, nas can't write to its backup folder. open backups"

Not drawn, same style: "backups for memex: never backed up. open backups"; "backups for memex: backing up. open backups"; "backups for work: nas's last backup today at 03:00. open backups";
"backups for work: set on nas. open backups"; "backups for work: not on nas yet. open backups".
The failure tail ("can't write to Google Drive", "nas can't write to its backup folder", …) is the `short` column of the message table in pack 325; for a manual run the first clause reads "back up now failed <day> at <HH:MM>"; `<day>` is "today", "yesterday" or "9 nov".

## Large text (1.3x, B4-3)

Use minimum height 28 with vertical padding 4 (the board draws the hosted row 30 high at 1.3x: 1 border + 4 + 20 text + 4 + 1). The label is 16.25 and the status 13.65 there.
When label and status do not fit one line, the row grows and the status wraps under the label text (indented past the icon and gap). Never clip or ellipsise the failure text. Pills wrap as they already do; the row follows the last pill line.

## Contrast

fg1 on surface1 12.95; fg2 on surface1 6.86; warn on warn-tinted row (`warnBg` over surface1) 11.17; fg2 on that tint 5.64; accent and info icons are non-text.

## Notes and mismatches

- WI says the row shows the last backup's age. The hosted ok row (B1-6) draws a clock time ("03:00"), not an age. The board wins; a hosted success on an earlier day is not drawn.
- WI AC lists "never": B1 draws no "never" state; the copy above ("never") comes from the board caption (`"never" before the first one`).
- The board draws no separate "badge". `backups-entry-warning` is pinned to the 12x12 warning icon; if the lead prefers the whole amber content (icon + label + time) as the badge, the Key moves to that `Row` with the same `IgnorePointer`.
- Failure time is the last attempt time of the failing run, 24 h `HH:MM`, from `backup-state.json` (local) or the server's `last_attempt_at` (hosted).
