## WI vs design (design wins)
- **Tab chip "not saved yet" is not drawn.** The A11·1 active tab shows only its title (the mock chip has no icon, no close, no marker). The WI says the tab "shows not saved yet". Derived (needs lead / Connor sign-off, listed in the return notes): a `StatusDot` in the *can't reach* look (6 px hollow `warn` ring, [pack 69](69.md)) after the title, gap 6, with tooltip and semantics label "not saved yet". Reason: the ring already means "couldn't reach the server", it needs no new asset, and it fits the 200 px chip (title ellipsises). Key `tab-pending-<tabId>`.
- The A10/A11 editor chrome is a simplified mock: it draws "note · edited 2 min ago" while today's `_MetaRail` (`note_header.dart`) shows a clock icon, "updated <ago>", "·", "<n> words" and a bottom `line1` rule. Only the new warn label is a design requirement; do not restyle the rest of the rail.
- The board draws the label alone in the meta position. Decision: while a save is pending the rail shows **only the label** (no stale "updated …"), keeping today's rail container (bottom padding 10, bottom border 1 `line1`); no clock icon. For the virtual Today note (no rail today) the same label row still shows. Key `pending-save-label`.
- After a 401 the label text stays "not saved yet · will save when <server> is back" (WI ruling; same string, same style).

## Editor label (A11·1)
- Text: "not saved yet · will save when <server> is back" (middle dot with single spaces; `<server>` = saved server name, board "nas"; lower case).
- JetBrains Mono w400 **11** px, line height 16.5, letter-spacing 0, colour `warn` `#FFD27A`, one line, left-aligned at the editor's content edge, directly above the serif title (the board's meta-to-title gap is 8; today's layout keeps its 18 px spacer).
- No icon, no background, no animation. It disappears when the queued save lands.
