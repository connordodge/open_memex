## WI vs design (design wins)
- Copy, eyebrows, header "vaults on <server> · <n>", loading text, empty text, buttons: all match the WI.
- **Failure states are not drawn** in either dialog (can't reach, 401 + update token, "couldn't confirm"). Derived from A5·3/4 (marked derived): an error row (`alertTriangle` 12 `danger` + JetBrains Mono 11 / 16.5 `danger`) directly under the server select, which takes the invalid border `danger.withAlpha(166)`. For 401 the row ends with a link "update token" (Inter Tight 12 `info`, key `server-dialog-update-token`). Keys: `server-dialog-error`. The "couldn't confirm with <server> — check before trying again" row (create only) uses the same style. In A6 the failure also replaces the vault list area (no skeleton, no rows).
- The board's server menu is **340 px wide** but its select is 422: draw the menu at the select's width (422). Items otherwise as drawn.
- WI "create is disabled after invalid_vault_name until the name changes": A7·2 draws it disabled (40%); A7·3 (`vault_exists`) draws it **enabled**. Matches the WI.
- The preview ("will be created at ...") is drawn only in A7·1; hide it while an error shows (A7·2, 3) and while the name is empty (not drawn, derived).
- Vault list longer than the dialog: not drawn; derived: scroll the list at about 6 rows (max height 250), keep header, link and actions fixed.
